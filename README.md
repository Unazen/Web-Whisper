# Whisper local

Локальное веб-приложение: нажал на кнопку, наговорил, получил текст. Распознавание идёт на твоей машине через faster-whisper (large-v3), в интернет ничего не уходит.

Стек: Python + FastAPI на бэкенде, чистые HTML/CSS/JS на фронтенде, автозапуск через systemd, HTTPS через Caddy.

## Что умеет

- запись с микрофона любого устройства, открывшего сайт (по кнопке или пробелом);
- прогресс и текст по мере распознавания (появляется по сегментам, ещё не в реальном времени);
- язык: автоопределение или выбор вручную;
- результат можно править в поле, правки сохраняются сами;
- автокопирование в буфер обмена и кнопка COPY;
- скачивание: TXT, SRT с таймкодами, исходное аудио, MP3;
- архив записей, автоудаление через 30 дней;
- очередь: одна запись обрабатывается за раз;
- модель грузится на GPU при первом запросе и выгружается через 5 минут простоя;
- если видеокарта занята (например, рендерится Blender) и свободно меньше 5000 МБ видеопамяти, модель работает на CPU. Когда GPU освободится, при следующей записи модель сама вернётся на него.

## Установка

Всё скачивается с нуля, ничего не берётся из кэша OpenWebUI.

```bash
cd ~/whisper-app
chmod +x setup.sh
./setup.sh
```

Скрипт создаёт `.venv`, ставит зависимости (включая cuBLAS и cuDNN для CUDA 12 через pip, системный CUDA Toolkit не нужен), проверяет `ffmpeg` и качает модель large-v3 (около 3 ГБ) в `models/large-v3`.

Для MP3 нужен ffmpeg: `sudo pacman -S ffmpeg`. Без него остальное работает, не работает только кнопка MP3.

Если pip ругается на `ctranslate2` или `av`, значит для твоей версии Python нет готовых пакетов. Тогда нужен Python 3.12: `rm -rf .venv && PYTHON_BIN=python3.12 ./setup.sh`.

## Этап 0: проверка Whisper в консоли

Перед запуском сайта проверь, что модель работает на видеокарте:

```bash
source env.sh
python scripts/proto.py путь/к/аудио.mp3
python scripts/proto.py путь/к/аудио.mp3 --device cpu
```

Скрипт покажет, на чём загрузилась модель, сколько заняло распознавание и во сколько раз оно быстрее реального времени. Если на GPU падает с ошибкой про `libcublas` или `libcudnn`, значит не подхватились пути к библиотекам, смотри ниже в разделе проблем.

## Запуск вручную

```bash
./run.sh
```

Откроется на `http://127.0.0.1:8765`. Микрофон в браузере работает на `localhost` и по HTTPS, но не по обычному `http://192.168.x.x`. Для доступа с других устройств нужен Caddy.

## HTTPS через Caddy

В `deploy/Caddyfile.example` пример:

```
whisper.lan:8443 {
	tls internal
	reverse_proxy 127.0.0.1:8765
}
```

Подставь свой хост или IP и порт и добавь блок в существующий Caddyfile. На каждом устройстве один раз нужно довериться корневому сертификату Caddy (или принять исключение в браузере), как ты уже делал для рендер-сервиса.

По умолчанию приложение слушает только `127.0.0.1`, наружу его выставляет Caddy. Если хочешь без Caddy в обход HTTPS (например, только для текстовых проверок), запусти с `WHISPER_HOST=0.0.0.0`, но микрофон по HTTP работать не будет.

## Автозапуск (systemd)

Юнит пользовательский, рассчитан на папку `~/whisper-app`:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/whisper-app.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now whisper-app
loginctl enable-linger $USER
```

`enable-linger` нужен, чтобы сервис стартовал при загрузке системы без входа в сессию. Логи: `journalctl --user -u whisper-app -f`. Если папка лежит в другом месте или рендер-сервис у тебя оформлен системным юнитом, поправь пути и `User=` по аналогии с ним.

## Настройки

Задаются переменными окружения (в юните через `Environment=`):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `WHISPER_HOST` / `WHISPER_PORT` | `127.0.0.1` / `8765` | адрес сервера |
| `WHISPER_MODEL` | `large-v3` | имя модели (`turbo`, `medium` и т.д., нужно скачать заново через setup) |
| `WHISPER_MODEL_DIR` | `models/<имя>` | путь к файлам модели |
| `WHISPER_MIN_FREE_VRAM_MB` | `5000` | меньше свободной видеопамяти, значит CPU |
| `WHISPER_IDLE_UNLOAD_SECONDS` | `300` | через сколько простоя выгружать модель |
| `WHISPER_RETENTION_DAYS` | `30` | через сколько дней удалять записи |
| `WHISPER_MAX_DURATION_SECONDS` | `1800` | максимальная длина записи |
| `WHISPER_CPU_THREADS` | `6` | потоков при работе на CPU |
| `WHISPER_DATA_DIR` | `data` | где лежат записи |

## Где что лежит

```
server/        бэкенд (main.py, jobs.py, transcriber.py, storage.py, export.py)
static/        интерфейс (index.html, style.css, app.js)
scripts/       проверка в консоли и загрузка модели
deploy/        systemd-юнит и пример Caddyfile
data/records/  записи: аудио, meta.json, mp3 по запросу
models/        файлы модели
```

## Возможные проблемы

**На GPU ошибка про `libcublas.so.12` или `libcudnn`.** Библиотеки ставятся pip-пакетами, а их путь подставляет `env.sh` в `LD_LIBRARY_PATH`. `run.sh` и systemd-юнит запускают его сами. Для ручных запусков Python используй `source env.sh`. Приложение в этом случае не падает, а само откатывается на CPU, режим виден в плашке вверху страницы (`ENGINE GPU` или `ENGINE CPU`).

**Распознавание на CPU очень медленное.** large-v3 на CPU тянет примерно в районе реального времени или медленнее. Это запасной режим на время рендера. Для быстрого CPU можно задать `WHISPER_MODEL=medium` или `small`.

**Текст не копируется автоматически.** Браузеры разрешают запись в буфер только на защищённой странице и в ответ на действие пользователя. Firefox строже Chrome. Если автокопирование не сработало, кнопка COPY подсветится.

**Рендер и Whisper вместе.** Если модель уже загружена на GPU, а ты запустил рендер, они делят 12 ГБ видеопамяти. Через 5 минут простоя модель выгружается сама. Если рендер тяжёлый, можно поставить `WHISPER_IDLE_UNLOAD_SECONDS=60`.
